# calculator-interview

> 招新考核训练场：一个只会加法的计算器网页，`js/main.js` 里只留了一个空的 `add()`。这里是组织里**唯一对外部候选人开放**的仓库，所以这里的规矩＝[guidelines](https://github.com/GXMZU-AITECC/guidelines)＋本页这一小段增补。

## 靠它进社团

不用打招呼：fork、提 Issue、提 PR。流程、红线、处分全在 guidelines 里，本页只写这个仓特殊的地方。通过标准只有一条——**PR 被合并**。入社之后不用再回来，内部协作走各项目仓库。

## 题目自己出

你觉得这个计算器还缺什么，就提什么功能提案；写法看 Issues 里标题带「示范」的那条。**没灵感就去抄现成的**：手机自带计算器、Windows 计算器、任意一个网页计算器，随便挑一个功能照做，照抄不扣分。范围不出这个网页：要装依赖、要引框架、要换语言的提案一律拒。

## 本仓增补（规范之外，只在这里生效）

| 增补 | 内容 |
| :--- | :--- |
| **只用原生 JS** | 不引框架、不装依赖、不加构建工具；逻辑写在 `js/main.js` 一个文件里，不拆分层 |
| **不碰骨架** | 显示区结构与 `css/style.css` 不动 |
| **验收要图** | PR 里附一张浏览器实际效果截图，没图不算做完 |
| **公开仓，内部资产** | 本仓对外可见，但题目、代码、Issue 与 PR 讨论都按社团内部资产对待（**P0**） |
| **评审不用你操心** | 外部账号没有 assign 权限：提完 PR 等就行。本仓用 CODEOWNERS 把评审自动派给 `reviewers` team，谁认领谁评审，第二名认领的 Reviewer 批准并合并 |
